本方案将 fluxvoice-personal 的模型目录、搜索、手动选择、缓存和配置交互思路移植到 my_brain，按现有 TypeScript / Expo 架构重新实现。保留 my_brain 的知识图谱、用户画像、记忆边界、语音确认、自动整理和打断机制。

原来的豆包配置保留，并作为可选择的实时语音提供商。语言模型设置整体替换为通用配置。TTS 新增独立提供商配置，第一批支持 OpenAI Speech 兼容协议和 MiMo 使用的 Chat Completions 音频协议。服务商有目录接口时自动获取模型和音色，没有时允许手动填写。

**“通用”指可配置、可扩展的协议适配架构。不能承诺任意一家 TTS 都只填 URL 和 Key 就可使用，也不能承诺接口没有公开的音色能够自动查到。** 特殊鉴权、签名、私有 WebSocket 或特殊音频格式需要增加适配器，不需要重写应用核心。

| 编号 | 用户需求 | 方案结果 |

| PC-01 | 移植配置相关代码，保持 my_brain 核心 | 移植目录与配置逻辑；不搬入源项目的聊天、记忆、人格或音频会话业务 |
| PC-02 | 语言模型支持 OpenAI 兼容接口 | 可填写 Base URL、Key、模型 ID；目录搜索或手动填写；保留原业务提示词与结构化输出校验 |

### 包含的必要接入修复

只改设置界面不能完成需求。本次还需要统一“连接测试”和“实际运行”的语言模型工厂，并接入通用 TTS 的音频输出、取消和状态回调。当前实际解释链路只为 `deepseek` 创建 live provider，其他选择会落到 mock；这必须在移植中修复。

陪聊页面当前使用本地临时会话逻辑。本次补齐服务调用入口时，继续使用现有临时会话、明确保存和确认入库出口；不把来源项目的整套聊天行为移入 my_brain。哪些页面和任务使用所选 LLM，实施时必须逐项验证。

### 不包含

- 改写知识图谱、记忆引擎、画像数据模型、入库确认和自动整理规则。
- 新云后端、跨设备同步服务、密钥代理服务或强制 BFF。
- 语音克隆、参考音频上传、音色设计工作流；这些模型可被发现，但不能在缺少所需参数时标为可用。
- 首批覆盖所有厂商的私有协议、所有 ASR 厂商或所有音频编码。
- 复制 Kotlin / Compose 界面、AudioTrack 实现、源项目系统提示词和固定中转站。
- 同时重做 legacy Web / Tauri 设置页，或借机修复全部历史测试问题。

## 3. 审批需要确认的产品选择

以下产品选择已经通过用户的实施计划确定。

| 决策 | 建议默认值 | 对用户的影响 |
| --- | --- | --- |
| A1：语音模式 | 保留“豆包实时会话”；新增“设备语音识别 → 所选 LLM → 所选 TTS”组合模式 | 豆包继续可用；组合模式可独立选择文字模型和声音 |
| A2：首批 TTS | OpenAI Speech 兼容协议、Chat Completions 音频协议；MiMo 作为后者的预设 | 后续厂商通过增加协议适配器接入；不做仅能接 MiMo 的专用设置页 |
| A3：目录失败 | 手动模型 ID / 音色 ID 始终可用，调用验证单独进行 | 没有 `/models` 或音色目录的服务也能配置；错误 Key 不会因手填而变成“已连接” |
| A4：主入口门控 | LLM 通过验证后可进入文字功能；语音能力未就绪时禁用语音并说明原因 | 不因 TTS 或麦克风故障锁住所有文字功能；属于现有全锁定逻辑的明确调整 |
| A5：地址范围 | 首批正式版使用公网 HTTPS，允许自定义路径前缀 | 本地 HTTP / 局域网服务作为后续明确扩展；不放宽 Token Exchange / Execution API 的限制 |
| A6：多配置 | 可以保存多份服务配置；每个角色同一时间只启用一份 | 可切换供应商；同一轮请求固定配置，防止混用密钥或重复播报 |
| A7：迁移与交付 | 保留旧配置回退副本；验证后交付版本递增、签名一致的 Android APK | 不清空用户脑图或旧豆包；升级安装可保留原应用数据 |

PC-10 是用户明确要求，不是待选项。不得在本机运行应用编译、构建或开发测试，再用本机结果替代 Actions 证据。云托管 runner 覆盖静态检查、服务模拟与 Android 模拟器；真实麦克风 / 蓝牙 / 可听停止时延等证据需 Actions 驱动的受控真机 runner。设备条件缺失时保留“未验收”，不能把模拟器结果当作真机通过。用户安装体验反馈可以补充自动化证据，不替代未运行的测试。

2026-10-07 已确定：首版发布 GitHub Prerelease 测试 APK；缺少真机环境不阻断该测试版，但必须列出未验收项目。移动端、共享核心和本次功能检查全部通过；无关且未恶化的旧 Web/Tauri 失败保留报告。LLM 已就绪时开放文字功能。首批 TTS 输出收敛为 PCM16LE 单声道；其他音频编码后续扩展。这些决定优先于早期草案中正式发布须完成真机验收的条款。

豆包实时会话由豆包会话服务处理语音回复；通用 LLM 设置用于 my_brain 的文字与知识任务。**如果要求每一句语音回复都由所选 LLM 生成，应选择组合模式。** 本次不声称修改一个 LLM 设置就能替换豆包实时会话内部的语言模型。

## 4. 核心机制的保护承诺

| 编号 | 必须保持的行为 |
| --- | --- |
| CP-01 | 新建概念节点仍经用户明确确认入库；服务连接、模型切换和 TTS 回调无图谱写权限 |
| CP-02 | 入库后自动 merge / archive / link / attach / edge-migrate 保留；结构变更有历史并可撤销 |
| CP-03 | 归档是隐藏，不硬删除；替换节点的边迁移保留 |
| CP-04 | 原始音频和全文不进入永久存储；知识图谱与用户画像保持独立 |
| CP-05 | 用户画像蒸馏仍静默执行；记忆引擎不直接写图谱或画像 |
| CP-06 | 用户打断后立即停止播报并转听；被取消请求的晚到音频不能恢复播放 |
| CP-07 | 数据仍以本地存储为主；Key 仅进入安全存储，不进日志、仓库、普通配置或构建包 |
| CP-08 | 真实服务失败明确报错；不能用静默 mock 或偷偷换供应商制造“已连接” |

核心机制的验证是交付门槛。设置页能保存、模型能列出、APK 能编译，都不足以单独宣布移植完成。

## 5. 已知事实与待实机验证项

- OpenAI 兼容 `/models` 通常提供模型 ID，不能可靠证明 TTS 能力或本账号实际调用权限。
- MiMo 有公开模型列表接口；已查官方文档中未发现公开音色目录接口。本次以官方音色预置和手填覆盖，界面标明来源，不能显示成“接口实时获取”。
- MiMo 普通 TTS、克隆、音色设计所需参数不同；第一批只实现普通文本合成。
- 当前豆包是双向实时语音链路，并非可以直接塞进普通 `synthesize(text)` 的 TTS。保留独立适配器。
- 当前设备 STT 在播报时有停止 / 忽略转写行为。组合模式要达到随时打断，需要实机验证持续语音活动检测或可用识别机制，不能仅靠取消按钮验收。
- Expo / RN 上流式 HTTP、SSE、音频编码和蓝牙行为需实测。优先复用现有 PCM 播放接口；若必须增加原生依赖，先给出原因与验证结果，不能无声扩大范围。

详见 [来源审计](SOURCE_AUDIT.md) 和 [验收清单](IMPLEMENTATION_AND_ACCEPTANCE.md)。接口事实核对日期为 2026-10-07，开发时需复核变化。
